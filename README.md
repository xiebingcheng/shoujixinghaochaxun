# 手机型号查箱号

输入手机型号（或箱号），查出它所在的箱子。箱号分 **S / L / Y** 三种开头，
同一个型号如果在多个箱子里都有，会一次全部列出来。

输入时会有**联想下拉框**：打一个 `i` 就把所有 i 开头的机型列出来供点选，
每条右侧还会显示它所在的箱号。

纯静态网站，可直接部署到 GitHub Pages，数据存成 JSON 文件。

另外还有一个功能一致的**微信小程序版**，见 [miniprogram/](miniprogram/)。

## 目录结构

```
docs/                      ← 网站本体（GitHub Pages 发布这个目录）
  index.html
  assets/style.css         ← 样式
  assets/app.js            ← 页面交互
  assets/search.js         ← 搜索逻辑（规范化 + 匹配打分）
  assets/favicon.svg
  data/boxes.json          ← 由脚本从 6 个表格生成的查询数据
  data/substitutes.json    ← 箱号替代关系（手工编辑，不会被脚本覆盖）
  data/model-sizes.json    ← 手机型号 → 屏幕尺寸（英寸），手工编辑
  data/sizes.json          ← 由脚本生成：型号尺寸表 + 每个箱号的代表尺寸
  manifest.webmanifest     ← 可“添加到主屏幕”
  sw.js                    ← 离线缓存（首次打开后无网也能查）
资料/                       ← 原始表格（两人各 3 份，共 6 份）
tools/build_data.py        ← 把表格生成 JSON + 数据核对报告
tools/gen_model_sizes.py   ← 生成「型号 → 屏幕尺寸」初版（批量补充用）
tools/build_sizes.py       ← 算出每个箱号的代表尺寸 + 覆盖率报告
tools/check_search.js      ← 搜索逻辑自测
tools/check_size.js        ← 尺寸查箱号功能自测（需要先起本地服务）
tools/inspect_data.py      ← 查看表格结构
reports/数据核对报告.md      ← d 版 / q 版 两份数据的差异清单
reports/屏幕尺寸覆盖报告.md  ← 屏幕尺寸覆盖情况 / 待补清单
```

## 本地预览

直接双击 `docs/index.html` 不行（浏览器不允许读取本地 JSON），要先起一个本地服务：

```powershell
python -m http.server 8123 --directory docs
```

然后浏览器打开 <http://127.0.0.1:8123/>。

## 修改数据

1. 直接编辑 `资料/` 里的 Excel（保持列结构不变）；
2. 运行：

```powershell
python tools/build_data.py
```

这一步会同时做两件事：

- 重新生成 `docs/data/boxes.json`（网站查询用）；
- 重新生成 `reports/数据核对报告.md`（两人数据的差异清单）。

## 两个人做的数据怎么对比

6 个表格是两个人各做 3 份（`d-*` 与 `q-*`），脚本会逐箱比对：

- 两边都有的型号 → 标记 **两人已核对**；
- 只有一边有的型号 → 标记 **待核对**，并写进 `reports/数据核对报告.md`。

报告里会列出每个箱号"仅 d 版有 / 仅 q 版有"的型号，照着它核对即可。
当前 131 个箱号、2554 条型号记录中，2395 条两人一致。

## 箱号替代关系（哪个箱号可以被替代）

两个箱子的机型可以互相替代：哪个箱子缺货，都可以用另一个箱子里的机型顶上。
搜索到其中任一箱的型号时，搜索结果里会分出一个「可替代箱号」分组，把能顶上的箱号单独列成卡片，
卡片上带橙色「可替代」标记并写明"S49（红米K80超声波解锁）缺货时，可以用本箱里的机型替代"；
原卡片底部也会留一行「可替代箱号」文字链接（浏览列表里同样有），点一下直接跳到那个箱号。

注意：可替代箱号**只跟着精确匹配走**。搜索的型号确实在某个箱子里（或直接搜箱号）时，
才会带出那个箱子的可替代箱号；只出现在「相近结果」里的箱子不会显示可替代箱号，
避免用户误以为它能替代自己正在查的箱号。

关系写在 `docs/data/substitutes.json` 里，一条一行，写成两个箱号用 `-` 连接：

```json
{
  "pairs": [
    "S49-S33",
    "S64-S59"
  ]
}
```

- `S49-S33` 表示这两个箱**互相替代**（搜 S49 会显示 S33，搜 S33 也会显示 S49）；
- 只想单向时写成 `S64>S59`（`>` 或 `→`），表示只有 S64 缺货时才用 S59；
- 同一个箱号可以写多条（如 `S61-S58`、`S61-S60`），表示它有多个替代箱号；
- 这个文件是手工维护的，`python tools/build_data.py` **不会**覆盖它；
- 改完直接刷新网页即可（手机端如已“添加到主屏幕”，下拉刷新一下）。

## 部署到 GitHub Pages

### 方式一：网页操作（不需要命令行）

1. 登录 <https://github.com>，点右上角 **+ → New repository**；
2. 仓库名随便取，比如 `phone-box-lookup`，选 **Public**，创建；
3. 进入新仓库，点 **Add file → Upload files**，把本项目的 `docs` 文件夹
   整个拖进去（拖文件夹，目录结构会自动保留）；
4. 上传后进入 **Settings → Pages**：
   - Source 选 `Deploy from a branch`
   - Branch 选 `main`，文件夹选 **`/docs`**，保存；
5. 等 1～2 分钟，访问 `https://你的用户名.github.io/phone-box-lookup/`。

> 网址里的路径要和仓库名一致。以后改数据，只要重新上传 `docs/data/boxes.json` 即可。

### 方式二：命令行

```powershell
git remote add origin https://github.com/你的用户名/phone-box-lookup.git
git push -u origin main
```

推送完成后，同样在 **Settings → Pages** 里选 `main` + `/docs`。

## 微信小程序版

网页版继续用 GitHub Pages 部署，两者互不影响；小程序版放在 `miniprogram/`，
功能和网页版一致（搜索、联想、S/L/Y 筛选、展开箱内机型、复制箱号、可替代箱号）。

要注意：小程序的请求域名必须 HTTPS 且已 ICP 备案并配进微信后台白名单，
`github.io` 配不进去，**小程序不能直接读 GitHub Pages 上的 JSON**。
所以数据是打进小程序代码包的（约 165 KB，离线可用），由脚本从 `docs/data/` 同步：

```powershell
node tools/build_mp_data.js    # 同步数据 + 搜索逻辑到 miniprogram/
node tools/check_mp.js         # 小程序版自测
```

详细的上手 / 发布步骤见 [miniprogram/README.md](miniprogram/README.md)。

## 搜索是怎么匹配的

- 边打边联想：输入 `i` → 列出 `iPhone11`、`iQOO13`… 点一条即可查；
  下拉框支持方向键上下选择、回车确认、Esc 关闭；
- 忽略空格、大小写、全角半角：`mate30 pro`、`Mate30Pro`、`mate30pro` 一样；
- 常用别名互通：苹果=iPhone、荣耀=honor、魔术/魔法=Magic、至臻版=至尊版 等；
- 品牌可省：输入 `X60Pro` 能查到 `vivo X60Pro`；
- 结果分「精确匹配」和「相近结果」两组，一次全部列出来（相近结果最多展示前 40 个）；
- 支持直接搜箱号（`S01`、`y07`）；
- 点卡片左上角的箱号（蓝色方块，带 ▾ 小三角）即可展开/收起，看到箱子里
  的全部机型；要复制箱号用卡片右下角的「复制箱号」按钮；
- 命中箱号（或箱内机型）时，会额外列出该箱的「可替代箱号」卡片（带「可替代」标记），
  卡片底部也有一行文字链接，点一下即可跳到那个箱号。

## 尺寸查箱号（按屏幕尺寸找替代箱号）

顶部有两个选项卡：**型号查箱号**（原来的功能）和**尺寸查箱号**。

**尺寸查箱号**解决的是「这个型号没覆盖 / 箱子里没货」的情况：输手机型号会先查它的
屏幕尺寸，再按尺寸远近列出可以现场试一试的箱号；也可以直接输尺寸（如 `6.5`）。
结果分三档：

- **尺寸一致**：差 ≤ 0.05 英寸；
- **尺寸接近**：差 ≤ 0.15 英寸；
- **勉强候选**：差 ≤ 0.30 英寸。

> 屏幕尺寸相近 **≠** 可以通用。结果只是把翻找范围从 100 多个箱号缩到几个，
> 最终一定要现场比对屏幕尺寸、比例、排线、开孔。页面上也有这句提示。

每个箱号右上角的小标签就是这一箱的屏幕尺寸（如 `6.5″`），
型号查箱号的结果里同样会显示。

### 箱号尺寸是怎么算出来的

按「抽箱内 60~80% 的机型就能代表这一箱」的思路，由 `tools/build_sizes.py` 计算：

1. 只统计有尺寸数据的箱内型号；
2. 覆盖率（有尺寸的型号占比）低于 **60%** → 不给结论；
3. 把尺寸按 0.1 英寸滑动分档，取型号最多的那一档；
4. 这一档的占比低于 **60%** → 说明箱内尺寸不统一，也不给结论。

目前 129 个箱号里 **84 个**能算出尺寸。没算出的大多是 2026 年新机型（尺寸还没录进去）
或箱内型号跨度确实很大的箱子，明细见 `reports/屏幕尺寸覆盖报告.md`。

### 维护屏幕尺寸数据

1. 编辑 `docs/data/model-sizes.json` 的 `models`：键写型号原文，值写英寸，
   例如 `"红米15": 6.9`。改对了就会覆盖自动生成的初版数值。
2. 运行：

   ```powershell
   python tools/build_sizes.py      # 重新生成 docs/data/sizes.json + 覆盖率报告
   node tools/build_mp_data.js      # 同步到小程序
   ```

`reports/屏幕尺寸覆盖报告.md` 会列出：哪些型号还没有尺寸、哪些箱号尺寸不统一
（多半是箱内型号数据本身有问题）、哪些型号被写成了两个不同的尺寸。

初版尺寸表由 `tools/gen_model_sizes.py` 按机型系列规则生成，**没经过人工核对**，
数字仅供参考，建议照着报告逐箱核对一遍。
